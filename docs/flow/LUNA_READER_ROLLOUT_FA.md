# تحویل قالب صفحات داخلی Flow به Luna

## نمونه‌های مرجع اعتبارسنجی‌شده

قالب Flow ابتدا روی **مهندسی کامپیوتر** ساخته شد و حالا به‌صورت کنترل‌شده روی پنج پروندهٔ واقعی فعال است:

| رشته | profile | خانواده adapter | نکتهٔ ساختاری |
| --- | --- | --- | --- |
| مهندسی کامپیوتر | `computer-engineering` | `engineering` | نمونهٔ پایه |
| پزشکی | `medicine` | `health` | طولانی‌تر و جدول‌سنگین؛ lead به‌شکل پاراگراف |
| حقوق | `law` | `humanities` | lead ساختاری و چند جدول/منبع |
| گرافیک (عنوان پرونده: ارتباط تصویری) | `graphic-design` | `art` | نمونهٔ هنر و طراحی |
| روان‌شناسی | `psychology` | `humanities` | تعداد جدول کمتر و متن‌محورتر |

نمونهٔ پایه:
`/flow-preview.html#major=computer-engineering`

در خروجی Cloudflare همین الگو از مسیر `/#major=<profile>` باز می‌شود. این سند نشانهٔ انجام دیپلوی زنده نیست.

این rollout هنوز **سراسری نیست**. رشته‌هایی خارج از registry، از جمله مهندسی برق، عمداً Reader قدیمی را حفظ می‌کنند تا خانواده‌های بعدی قبل از فعال‌سازی بررسی شوند. استان‌ها و مقالات نیز هنوز تعمیم داده نشده‌اند.

## فایل‌های اصلی و قرارداد قالب

| فایل / نشانه | مسئولیت |
| --- | --- |
| `public/flow/reader.css` | ظاهر خواننده؛ تمام قواعد زیر `body[data-flow-reader="major"]` محدود شده‌اند |
| `public/flow/reader.js` | registry آداپترها، بسته‌بندی بخش‌های تخت، اصلاح پرش بازار و برند رابط |
| `public/flow/tokens.css` | رنگ‌ها، فونت و مقیاس مشترک Flow |
| `public/flow/theme.css` و `theme.js` | صفحهٔ اصلی موجود؛ مرجع هویت بصری |
| `scripts/build-flow-preview.mjs` | افزودن فایل‌های قالب به خروجی؛ فایل اصلی بازنویسی نمی‌شود |
| `tests/e2e/flow-reader.spec.ts` | برابری محتوا، رفتار، تاریخچه، holdout و عرض‌های مختلف برای پنج نمونه |
| `docs/flow/references/reader-desktop.webp` و `reader-mobile.webp` | تصاویر نمونهٔ اجرای اولیه |
| `.page[data-aris-profile]` | شناسهٔ واقعی پرونده؛ نام نمایشی یا متن فارسی معیار تشخیص نیست |
| `data-flow-reader-template="1"` | جلوگیری از تزئین تکراری همان سند |
| `data-flow-reader-adapter` | خانوادهٔ adapter فعال روی پرونده |
| `.flow-reader-section` | بسته‌بندی H2 تخت همراه با محتوایش، بدون کپی‌کردن گره‌ها |

رویدادهای جست‌وجو، تغییر hash، تاریخچه، جدول‌ها و جزئیات توسط موتور اصلی اجرا می‌شوند. Observer فقط فرزندان مستقیم `#major-document` و تغییر `hidden` خواننده را می‌بیند.

Discovery واقعی نشان داد پنج نمونه ساختار هستهٔ مشترک دارند، اما جزئیاتشان برابر نیست: پزشکی ۷ جدول دارد، حقوق و گرافیک/ارتباط تصویری ۵ جدول، روان‌شناسی ۴ جدول و نوع بلوک lead هم یکسان نیست. بنابراین registry حفظ شده و هنوز حذف allowlist/فعال‌سازی ۳۴۲ رشته مجاز نیست.

اصلاح ناوبری بازار کار عمومی شده است: بعد از بسته‌بندی H2های تخت، تیتر واقعی بازار/درآمد به `data-aris-section="market"` متصل می‌شود تا پرش زیر فهرست ثابت فرود بیاید. تست این رفتار را روی هر پنج نمونه و عرض‌های ۳۲۰، ۳۹۰ و ۷۶۸ بررسی می‌کند.

## معیار ظاهری

- زمینهٔ سرمه‌ای `--flow-bg`، سطح پنل `--flow-surface`، متن روشن `--flow-text`؛ فیروزه‌ای برای عملیات و سبز برای تأکید.
- فونت Vazirmatn موجود، RTL، متن ۱۶ پیکسل دسکتاپ و ۱۵ پیکسل موبایل؛ عرض خواننده حداکثر ۱۱۲۰ پیکسل.
- سربرگ داخلی کوتاه، برگشت واضح، معرفی رشته با تصویر کتاب موجود در دسکتاپ. تصویر تزئینی روی موبایل پنهان می‌شود.
- فهرست اصلی، جدول‌ها، details، کارت‌های خلاصه، مقایسه و منابع باید listenerها و محتوای اصلی خود را حفظ کنند.
- نام رابط و دعوت به کانال: **Flow** و `https://t.me/Flow_Konkour`.
- ارجاع نویسنده، منابع، تاریخ بازبینی و اشاره‌های تحریری به آریس حفظ شوند. جایگزینی سراسری «آریس» در متن مجاز نیست.

## مسیر بعدی تعمیم

۱. از registry پنج‌تایی فعلی به‌عنوان baseline استفاده کن و نمونه‌های جدید را قبل از اضافه‌شدن با discovery ساختاری بررسی کن.

۲. اگر DOM خانوادهٔ جدید با این پنج نمونه سازگار است، profile آن را به adapter مناسب اضافه کن و تست برابری محتوا + responsive را گسترش بده. اگر ناسازگار است adapter جدید بساز؛ صرفاً profile را به لیست اضافه نکن.

۳. بعد از پوشش خانواده‌های اصلی رشته‌ها، rollout رشته‌شناسی را دسته‌ای انجام بده و یک holdout واقعی تا آخر نگه دار تا فعال‌سازی ناخواستهٔ سراسری قابل تشخیص باشد.

۴. استان‌ها را با همان توکن‌ها ولی ساختار متناسب با فصل‌ها، شهرها و دانشگاه‌ها طراحی کن؛ سپس مقالات را جداگانه هماهنگ کن.

## پذیرش و بررسی

- `public/index.html` باید دقیقاً ثابت بماند. SHA256 مرجع: `ebb69da2b9154a4ad1ca578bf6bb9409aba4846715260cd7d706964b35dfdee2`.
- تیترها، پاراگراف‌ها، لیست‌ها، متن جدول‌ها و href منابع قبل/بعد برابر باشند.
- باز کردن از جست‌وجو، لینک مستقیم، reload، بستن، Back/Forward و رفتن از سربرگ به جست‌وجو بررسی شوند.
- جدول‌های عریض فقط داخل ظرف خود اسکرول شوند و document بیرون‌زدگی افقی نداشته باشد.
- عرض‌های ۳۲۰، ۳۹۰، ۷۶۸ و دسکتاپ بررسی شوند.
- خروجی Next و Cloudflare باید همین UI را ارائه کنند.
- بررسی‌های ریپو: `npm run lint`، `npm run typecheck`، `npm run test`، `npm run build`، `npm run test:e2e` و `npm run check:cloudflare`.
